# Description

Add counter-based HOTP (RFC 4226) and Steam Guard codes next to the existing TOTP support.

Already implemented and out of scope: TOTP with SHA-1/256/512, 6–9 digits, custom period, `otpauth://` and native KeePass `TimeOtp-*` storage, QR import, browser fill.

Goals:
- Read, show, edit and create HOTP and Steam entries compatible with other clients.
- Steam: KeePassXC `otpauth://totp/...?encoder=steam` and KeeOtp `TOTP Settings` = `30;S` (both detected by KeePassKit `hasSteamOTP`); 5-character code from the Steam alphabet, 30 s period.
- HOTP: native KeePass 2.47+ fields `HmacOtp-Secret` / `-Hex` / `-Base32` / `-Base64` and `HmacOtp-Counter` (the only cross-client format). `otpauth://hotp?...&counter=N` from QR codes or imports is converted to the native fields.

Stack: Swift 6.1, SwiftUI, KeePassKit (`KPKHmacOTPGenerator`, `KPKSteamOTPGenerator`, `KPKEntry.hasHmacOTP`, `generateHmacOTPUpdateCounter:`). No new libraries, no new design: existing `KMSegmentedControl`, `.kmField`, `OTPRing`, `KMButtonStyle`.

## Decisions

- **HOTP in the entry window**: the current code is always shown; copying does **not** advance the counter. A separate "Next code" button advances it (+1) and saves.
- **HOTP outside the entry window** (browser `get-totp`, Quick Access copy, `{TOTP}`/`{HMACOTP}` placeholders when resolved for filling): handing out a code advances the counter and saves.
- `get-logins` responses don't include HOTP codes (they are built for every candidate and would advance counters just by listing). Verify with KeePassXC-Browser that TOTP fill goes through `get-totp`.
- Counter changes create **no history version** and are **not** registered in undo (undo would bring back a used code). Only the counter and modification time change.
- Merge: the HOTP counter of the result is the **maximum** of both sides, regardless of which entry version wins.
- Editor: OTP type selector TOTP / HOTP / Steam. HOTP shows algorithm, digits and counter (no period); Steam hides algorithm, digits and period. HOTP is always stored natively (storage style picker hidden).
- Detail card: TOTP and Steam keep the ring and countdown; HOTP shows the code, counter number and "Next code" button instead of the ring.

# Implementation

## Step 1: Domain model
[x] Add `VaultOTPKind` (`totp`, `hotp`, `steam`) to `VaultOTPConfiguration` and `VaultOTPForm`, with `counter` for HOTP
[x] Extend `OTPCodeGenerator` / code state: HOTP code for a counter (no remaining seconds), Steam code (5 characters, Steam alphabet)
[x] Search `is:otp` covers all kinds; Database Report coverage counts all kinds

## Step 2: Loader read/write
[x] Stop skipping Steam and HOTP in `makeOTPConfiguration`; read Steam via `hasSteamOTP`, HOTP via `hasHmacOTP` and `HmacOtp-*` fields
[x] Write HOTP as native `HmacOtp-Secret-Base32` + `HmacOtp-Counter`; write Steam as `otpauth://totp/...?encoder=steam` (+ native settings when native style is chosen); clear stale OTP fields of other kinds when the kind changes
[x] `advanceHOTPCounter(entryID:)`: +1, save immediately, no history snapshot, no undo registration
[x] Merge: after `synchronize`, set each HOTP entry's counter to the maximum of local and incoming values
[x] `otpauth://hotp` parsing (QR, import, editor URI paste) converted to native fields

## Step 3: Entry editor
[x] OTP kind selector (`KMSegmentedControl`, identifiers `editor.otpKind.*`)
[x] Per-kind options: HOTP algorithm/digits/counter, Steam no options, TOTP unchanged
[x] QR reader: accept HOTP codes (remove the `unsupportedHOTP` rejection), detect Steam URIs

## Step 4: Detail card
[x] HOTP row: code, "Counter N", "Next code" button (`detail.nextOTP`); copy doesn't advance
[x] Steam row: same as TOTP with 5-character formatting
[x] Localize new strings (en/ru)
[x] Undo/redo of an older edit doesn't bring back a lower HOTP counter

## Step 5: Browser, Quick Access, placeholders
[x] `browserTOTP(forEntry:)`: HOTP returns the current code and advances the counter
[x] `get-logins`: omit HOTP codes; keep TOTP/Steam
[x] Quick Access copy of an HOTP code advances the counter
[x] `{TOTP}` / `{HMACOTP}` resolution for filling advances HOTP — not needed: KeeMac doesn't resolve OTP placeholders anywhere (no Auto-Type yet)
